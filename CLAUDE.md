# kern

> Svelte 5 component kit (npm name `@mozra-the-great/kern`): one set of accessible components,
> many brands. Themes set colour, shape, depth, type and motion via `--k-*` CSS
> variables. Also shipped as framework-free custom elements (`<k-button>` …).

## Type
Library (UI component kit) with a demo site.

## Stack
Svelte 5 (runes, snippets), TypeScript 6, Vite 8, `@sveltejs/package` 3, svelte-check 4.
TypeScript 7 waits for svelte-check support (Dependabot ignores its major).
No runtime dependencies besides Svelte, no Tailwind.

## Structure
```
src/lib/components/   Svelte components (one file each) + anchor.ts, toast.svelte.ts, announcer.ts (shared live-region
                      store), strings.ts / strings.svelte.ts / strings-de.ts (default-text catalogue), prose.ts,
                      accent.ts + accent-themes.ts (accent API; ACCENT_GROUNDS mirrors the theme surfaces,
                      tests/tokens/accent-themes.test.ts fails when a theme changes and the table does not)
src/lib/themes/       base.css (all --k-* tokens), brands/<brand>.css (theme rules),
                      <brand>.css (self-contained entry: base + one brand), index.css (all),
                      accent.css (opt-in CSS-only accent fill, not in index.css)
tests/tokens/         Vitest (node project): theme contrast, per-brand entry isolation (npm test)
tests/unit/ tests/components/  Vitest (node project): logic and server-rendered markup (svelte/server, no DOM)
tests/dom/            Vitest (dom project, jsdom + @testing-library/svelte): smoke test of every export (smoke.test.ts)
                      and behaviour tests per component; env.ts = jsdom stand-ins (dialog, matchMedia, observers)
tests/targets/        Playwright: touch targets and 320 px reflow of the built demo (npm run test:targets)
src/lib/index.ts      public exports (components + types)
src/elements/         custom-element wrappers K<Name>.svelte; form.ts, control.svelte.ts + native.ts
                      (attribute forwarding, ElementInternals validity), define.ts (idempotent
                      registration), types.ts (+ types.check.ts), global.ts, index.ts (all-in-one)
custom-elements.json  Custom Elements Manifest, generated by scripts/elements-manifest.mjs
                      together with the .d.ts files (checked in, CI fails if stale)
tests/elements/       Playwright: custom elements in forms, attributes, validity, entries
tests/fixtures/react-jsx/  strict TS + React 19 fixture for the element typings
tests/fixtures/strict-consumer/  Svelte app with stuffcloud's strict TS flags, uses every component from dist/
src/demo/             demo app (App.svelte + sections/), themes.ts
assets/<brand>/       optional brand artwork (Code pixel art), exported as @mozra-the-great/kern/assets/*
index.html            Svelte demo · elements.html: custom-elements demo
```

## Commands
```sh
npm install
npm run dev     # demo: /index.html and /elements.html
npm run check   # svelte-check, must end with 0 errors / 0 warnings
npm run lint    # ESLint + prettier --check; must pass (no `any`, see eslint.config.js)
npm run format  # prettier --write + eslint --fix (formatting-only commits go into .git-blame-ignore-revs)
npm run build   # dist/ (package), dist-elements/kern-elements.js, demo-dist/
npm test        # Vitest, both projects: node (theme contrast, brand isolation, units, markup) + dom (jsdom component behaviour)
npm run test:coverage # Vitest + v8 coverage over src/lib (text report, coverage/lcov.info); fails below the ratchet in vitest.config.ts
npm run test:targets  # Playwright touch targets (after build; npx playwright install chromium)
npm run test:elements # Playwright custom elements (after build; npx playwright install chromium firefox, Firefox runs only a11y-tab-strip.spec.ts and the pill-strip test of a11y-reflow.spec.ts)
npm run test:types    # tsc on the React 19 typing fixture
npm run test:consumer # svelte-check --fail-on-warnings on tests/fixtures/strict-consumer (after build)
npm run check:dts     # published .d.ts: no `any`, no mutable input array (readonly-arrays-dts.mjs; after build)
npm run check:html    # no {@html}/innerHTML & co. in src/lib and src/elements (also a CI step)
npm run size          # size budget of the elements bundles (+10 % over baseline fails)
```

Release: bump `version`, move `[Unreleased]` in CHANGELOG.md to a dated section, merge, then
push tag `vX.Y.Z` on `main`; `.github/workflows/release.yml` attaches the `npm pack` tarball
and checksums to the GitHub release. Consumers pin that tarball URL (README, "Installation
und Pinning"). 0.x: minor = may break, patch = no break. Svelte minimum is `^5.20.0`;
CI builds on Node 22 + 24 and on the lowest/newest Svelte inside the `build` job
(keep the job id `build`, it is the required check).

## Notes
- Components read only `--k-*` tokens. Every component must look right in
  Code (square, hard offset shadows, mono uppercase labels, `steps()` easing)
  and Flower (soft, pills); check both themes, light and dark, desktop and 320 px.
- A new theme = `themes/brands/<name>.css` overriding the tokens of `base.css` for
  `[data-theme^='name']`, an entry `themes/<name>.css`, an `@import` in `themes/index.css`
  and an `exports` entry; it must pass `npm test` (contrast). Interactive parts use
  `--k-tap-target` (min size or invisible `::after` hit area). Themes: code,
  flower, pop, line (each from its design-system artifact; line is the Kagi-based one). `code` was called
  `stuffcloud` until #85: the old `data-theme` values, `themes/stuffcloud.css`, `assets/stuffcloud/*` and the
  `*StuffcloudArt` / `STUFFCLOUD_ART` exports are deprecated aliases until 1.0 (no new code uses them; the
  stuffcloud app itself stays "stuffcloud").
- The `K*.svelte` wrappers are not in `tsconfig.include`, so `npm run check` does not see
  them; `npm run build` compiles them. Every `emit()` in a wrapper needs an `@event`
  comment with the detail type, otherwise the manifest generator fails. Elements fire
  events for user input only, never while Svelte renders (React 19 bridge, #29/#30). The
  `k-` prefix is fixed; `define()` is idempotent and leaves foreign `k-*` tags alone. In a wrapper, a `<slot>` inside a
  `{#snippet}` needs the snippet to read a variable (`{#if footer}`), otherwise
  Svelte hoists it and it throws `$$props is not defined`.
- Overlays use `position: fixed` without a portal; inside shadow DOM, compare
  focus via `getRootNode().activeElement` and outside clicks via `composedPath()`
  (helpers in `anchor.ts`).
- Default UI strings are English and overridable via props; the demo and README
  are German. The defaults are the catalogue in `strings.ts` (by component and name) with a complete
  German bundle in `strings-de.ts` (typed, a missing text does not compile). A component never writes an
  English literal as a prop default: it destructures `label: labelProp` and reads
  `const label = $derived(labelProp ?? strings().section.label)` (`strings.svelte.ts`, reactive, so a
  language change reaches mounted components); `tests/unit/strings.test.ts` enforces both. Components that
  format numbers or dates use `formatLocale(locale)`. The state is shared with the other build via
  `globalThis[Symbol.for('kern.strings')]` (like the toast queue and `kern.announcer`). Never use
  `{@html}`, `innerHTML` & co. (`check:html`); text from props is always a text node (`Prose`, `parseProse`).
- Input-only list props and the array fields of exported item types are `readonly X[]` (like SortableList/SelectGrid),
  so a consumer's `readonly` or `as const` data is accepted (#142); copy before `sort`/`splice`/`reverse`. Only bindable
  outputs (`FileDrop.files`, `TagInput.value`, `DataTable.selected`, `TreeView.expanded`, `Resizable.sizes`) and callback
  arguments stay mutable. The wrappers' `@prop` types (src/elements/types.ts too) follow the same rule.
  `scripts/ci/readonly-arrays-dts.mjs` (part of `check:dts`) fails on any other mutable array property in the
  published `.d.ts`; a new bindable output goes into its `OUTPUTS` list.
- Optional props are declared `foo?: T | undefined` (consumers use `exactOptionalPropertyTypes`),
  and `undefined` must behave like a missing prop. `$bindable()` gets no fallback value
  (Svelte throws for `bind:x={undefined}` when it has one); apply the default where the value is
  read (`value ?? ''`, a `$derived`, or a function binding `bind:value={() => value ?? '', (v) => (value = v)}`).
  Merge option objects with `withDefaults()` (data-utils.ts), not a spread. New components go into
  tests/fixtures/strict-consumer (coverage.mjs fails otherwise) and into the `SMOKE` table of
  tests/dom/smoke.test.ts (`every export has an entry` fails otherwise). Component behaviour (props, bindable
  values, callbacks, keyboard, focus, ARIA, states) is tested in tests/dom/<component>.test.ts with
  `@testing-library/svelte`; read docs/testing.md first (props named `target`, `reactive()` for `bind:`, the
  jsdom stand-ins). Coverage has a ratchet: the thresholds in vitest.config.ts are the current numbers rounded
  down, so a PR that lowers coverage fails; raise them when coverage grows (goal 95 %, stage 2 of #24).

## Working rules

These rules apply regardless of what's above. They mirror the operator's global
Claude Code configuration so this repo behaves consistently even if opened on a
different machine or by a collaborator.

### Language
- Chat responses: German
- Everything that goes into the repo — code, comments, commit messages, branch
  names, PR descriptions, CHANGELOG: English (default, more compact)
- Respect a project's already-established language convention if one exists

### Approach — get it right once instead of fixing it ten times
1. Fully understand the task before starting
2. Think through the solution: edge cases, error handling, dependencies, blast radius
3. Only then implement it completely and correctly

No placeholders. No `// TODO` without a resolution attached. No half-finished
implementations.

For larger tasks: use Plan Mode before writing code. If something is fundamentally
unclear and would change the direction of the solution, ask once rather than
building in the wrong direction.

### Coding rules
- TypeScript: no `any`, explicit types
- Conventional Commits: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`
- Follow the project's existing conventions over these defaults when they conflict

### Git workflow
- Never commit directly to `main`/`master` — always a feature branch
- Branch names in English, kebab-case (`feat/...`, `fix/...`)
- Before every push: check `git status` and `git diff --staged`
- No `git push --force` on main/master

### Security
- `.env`, `.env.*`, `*.pem`, `*.key`, `*.secret` — never read, log, or commit
- No credentials/tokens/passwords in code
- Secrets via environment variables or a secrets manager, never in plaintext

### Subagents — delegate proactively
Use these specialists without being asked each time, as soon as the situation fits:

- **test-runner** → right after writing or changing application code
- **security-reviewer** → after auth/input/dependency changes, and before any release
- **code-reviewer** → before a merge / after finishing a feature
- **debugger** → as soon as a test fails, a stack trace shows up, or behavior is unexpected

Run independent analyses (e.g. security + tests) in parallel. Skip subagents for
trivial changes — the overhead isn't worth it.
